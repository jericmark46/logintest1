The repo is split into two independently deployable Vercel projects under `backend/` and `frontend/`; they share no code but agree on a small REST contract (`POST /api/auth/register`, `POST /api/auth/login`, `GET /api/auth/me`, `GET /api/health`) plus a JWT bearer-token scheme. The frontend stores the token in `localStorage` and attaches it via an `Authorization: Bearer` header through its fetch wrapper, while the backend's middleware validates the token against `JWT_SECRET`. CORS is configured per-deployed origin via the `CLIENT_ORIGIN` env var so the two Vercel domains can talk to each other. Both sides are wired for Vercel serverless/static hosting (`backend/api/index.js` entry point with Mongoose connection caching, `frontend/vercel.json` SPA fallback).
